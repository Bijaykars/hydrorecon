## Terrain without keys — the decision

**Primary: Re:Earth Terrain (terrain.reearth.land) — global, keyless, hosted quantized-mesh. Verified live:**
- `GET /cesium-mesh/ellipsoid/layer.json` → 200, `Access-Control-Allow-Origin: *`,
  `"format":"quantized-mesh-1.0"`, zoom 0–14, global bounds, tileset `mapterhorn-egm08@5`.
- Nepal tile `/cesium-mesh/ellipsoid/10/1507/682.terrain` → 200,
  `application/vnd.quantized-mesh`, CORS `*`, Cloudflare (served from a Kathmandu PoP in test).
- Also serves Terrarium PNG + Terrain-RGB tilejson for MapLibre. No tokens, no signup.
- Attribution required: "Re:Earth Terrain · Mapterhorn (CC BY 4.0)". Best-effort, no SLA.
- Lineage: Mapterhorn DEM (Copernicus GLO-30 over Nepal, CC-BY-4.0) + EGM2008 → ellipsoidal
  heights (exactly what Cesium wants). Repo: github.com/reearth/reearth-terrain (MIT, active).

**Fallback A (runtime):** `@macrostrat/cesium-martini` meshing AWS Terrain Tiles
(`elevation-tiles-prod` — re-verified `Access-Control-Allow-origin: *` on GET; HEAD is not
CORS-allowed, don't be fooled; SRTM-era data over Nepal, last modified 2017).

**Fallback B (self-hosted):** `tum-gis/cesium-terrain-builder-docker` (`ctb-tile -f Mesh -C -N`)
over Copernicus GLO-30 clipped to Nepal → static z0–14 tileset. Alternatives:
Gaia3D/mago-3d-terrainer, Geodan/terrain; index at bertt/awesome-quantized-mesh-tiles.
Mapterhorn publishes full Terrarium-WebP PMTiles on source.coop for subsetting.

**Underground/flythrough (Cesium 1.144 confirmed):** `Globe.translucency`
(`frontFaceAlpha`, `backFaceAlpha`, `…ByDistance`, `rectangle`) purpose-built for viewing
underground objects; `scene.screenSpaceCameraController.enableCollisionDetection = false` for
subsurface navigation; chained `camera.flyTo` / `SampledPositionProperty` + tracked entity for
alignment flythroughs.

**Vite integration:** `vite-plugin-cesium` is stale (Aug 2024, peer cesium ^1.95) — skip.
Official pattern: CesiumGS/cesium-vite-example — `vite-plugin-static-copy` for
Workers/Assets/Widgets/ThirdParty + `CESIUM_BASE_URL` define; plain ESM imports work (≥1.114);
consider `@cesium/engine` for a lighter build. `resium` 1.25.0 is React-19-ok but typings lag
Cesium releases — prefer raw Cesium in a ref/effect component.

## PMTiles / offline / static hosting

- MapLibre via `Protocol` (`addProtocol`). **No Cesium adapter exists** — would need a small
  custom `ImageryProvider`; Cesium *terrain* from PMTiles is not a thing.
- Vercel static serving verified: `206 Partial Content` + `Accept-Ranges: bytes` from the CDN —
  FlatGeobuf/COG/PMTiles range reads work same-origin from `public/`.
- Offline field mode: do NOT rely on service-worker caching of ranged responses (unreliable).
  Let users download the `.pmtiles` archive; open via `FileSource` (confirmed in 4.5.0 typings)
  or store in OPFS.
- Vercel Hobby limits: ~100 MB per file, 100 GB/mo bandwidth. Big archives → split or host on
  R2/source.coop (keyless-readable with CORS).

## Charts

**ECharts 6.1.0** — one Apache-2.0 dep covers FDC bands, monthly bars, tornado (stacked bar),
Pareto scatter, parallel coordinates, brush/dataZoom; canvas + progressive rendering makes a
15k-point daily series trivial. uPlot (21 KB) is faster raw but lacks half the chart types;
visx means hand-assembling everything. Long-profile/HGL stays bespoke regardless.

## Risks

1. Re:Earth Terrain is young, no SLA, may add rate limits → abstract the terrain source; keep
   cesium-martini+AWS fallback; self-build Nepal tiles long-term.
2. Re:Earth maxzoom 14 / Copernicus 30 m — fine for prefeasibility, not detailed design; user
   COG DTM patches (geotiff.js + martini) are the upgrade path.
3. AWS Terrain Tiles = Mapzen legacy (SRTM over Nepal, 2017): voids/artifacts in steep terrain.
4. Cesium weight ~1.7 MB gz → lazy-load 3D route only.
5. MapLibre v6 migration eventually (ESM+WebGL2); v5 fine today.
6. maplibre-contour 0.1.0 API immaturity; geotiff v3 breaking changes vs old examples;
   cesium-martini limited high-zoom testing (verify Terrarium decoder wiring);
   flatgeobuf bundler quirks (test in Vite early); ECharts tree-shaken size unverified.

## Dead ends checked

- Cesium World Terrain / ion — token required even free ⇒ violates no-keys.
- MapTiler terrain — key mandatory.
- vite-plugin-cesium — stale; superseded by official Vite example.
- Upstream cesium-terrain-builder — heightmap-only, quantized-mesh never landed (use tum-gis fork).
- PMTiles→Cesium adapter — does not exist.
- ctod (COG→terrain on demand) — needs a server ⇒ violates static-only.
- PDOK/Swisstopo/Corsica open quantized-mesh — keyless but regional, no Nepal.
- Three.js DIY globe — would badly recreate Cesium (LOD streaming, picking, translucency).
